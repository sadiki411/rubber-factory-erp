# 艾斯霖采购单图片导入与件数出货

## 已确认的业务范围

- 客户提供采购单图片，没有客户流程卡或扫码单。
- 同规格、同材质的采购单允许沿用现有多订单合并生产。
- 实际出货按包装好的成品件数登记，并且明确归属所选择的采购单项次。
- 库存保持独立，不因为导入采购单而自动入库、出库。
- 采购单图片不能证明历史生产、检验、出货或退货已经发生，不补造这些记录。

## 操作入口

1. 订单管理 → 导入订单 / 发料单 → 展开“艾斯霖采购单图片导入（PNG / JPG）”。
2. 可一次上传1–10张图片，单张不超过10MB，总计不超过20MB。
3. 图片由服务器本地Tesseract识别，不上传外部AI服务；识别只形成草稿。
4. 对照原图核对采购单号、日期、规格、材质、数量和交期。识别不清的字段须人工补齐，可新增或移除误识别明细。
5. 勾选核对确认后预检，再确认整批导入。有错误时整批不写入业务表。
6. 品检出货 → “采购单件数出货（无流程卡）”，选择采购单并记录本次出货。
7. 无卡产品退回时，使用“登记件数退货（无流程卡）”，选择原件数出货记录，回冲原采购单。

出货单号是ERP内部出货记录身份，不是客户流程卡号。没有流程卡的出货不伪装成扫码出货。

## 关联与保护

- 采购单唯一身份：艾斯霖来源 + 采购单号 + 明细项次。原图没有项次时，预览提供明细序号用于核对。
- 同图重传、改文件名或换上传顺序均不能重复增加采购数量。
- 产品资料按完整规格和材质匹配（不区分大小写）；多条匹配时展示候选档案，必须人工明确选择后重新预检，不默认取第一条，也不修改或合并旧档案。
- 原图没有的料长、料重、孔数、工艺和手工维护字段不会被图片导入清空。
- 产品编号与现存模具型号完全一致时才可自动绑定；未匹配到的不新建或猜配模具。
- 单价、金额作为采购单原始信息留存，不生成财务结算事实。
- 原图以ZIP保存在受保护的业务导入目录，OCR原文和人工核对后的内容分开保存。
- 件数出货只归属选中采购单，不自动分配到其他采购单；艾斯霖出货按净有效交付余量校验，退货释放对应余量。
- 无流程卡件数出货不会猜填品检员。登记前须确认本次件数对应已品检合格的包装成品；此确认不代表其他未出货产品已经检验。
- 新建艾斯霖件数出货和退货时，页面为本次操作生成稳定 UUID 请求标识。网络失败后原样重试只返回已保存记录，不重复记账；同一标识不能改参数后复用，也不能在修改记录时换掉。没有标识的请求会明确报错。
- 图片导入不自动补关联历史发料单，避免同号、同项次的其他来源资料被误认领。

## 验证口径

- 后端覆盖图片校验、草稿不写业务表、人工确认保护、五单数量、重复上传、已有产品保护、来源隔离、金额校验及模具匹配。
- 件数出货覆盖无流程卡/重量/员工的数据通路、退货回冲、修改、重入与并发余量保护。
- 前端覆盖图片编辑使预检失效、异步返回乱序、必填校验、明细增删、重复提交及出货入口。
- 自动浏览器可验证桌面和手机窄屏布局，但不能代替安卓真机的文件选择、实际出货和现场操作验收。
- 正式导入前需备份。导入后对旧业务记录逐行比对，只允许新增本次授权的采购单与必要产品档案，不重算旧账。
