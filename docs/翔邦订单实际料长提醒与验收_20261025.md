# 翔邦订单实际料长提醒

## 确认的业务规则

- 只比较本次订单文件中的客户料长与产品规格资料中手工维护的“实际切料长”，单位mm；不以旧客户料长作基准，不比较重量或模具号。
- 绝对差值大于5mm才提醒；正负5mm边界均不提醒。偏短突出标记，偏长同样提醒。
- 实际值未填、新产品、客户值未提供、复杂文本不能明确识别为单个毫米值、档案身份不唯一时，明确提示人工核对，不猜配或猜填。
- 提醒不是业务错误。未填实际值也可勾选“已知悉上述料长提醒，仍继续导入”后导入；确认不代表实测已完成或客户已经更正。
- 不更改原有订单关联方式；已明确关联且规格材质吻合时使用该档案，否则只使用唯一的同规格同材质档案。有多条候选时不取第一条。
- 导入不覆盖实际切料长、实际切料重，不重算或修改历史订单数量、出货和库存。

## 使用与实现

1. 订单管理→导入订单/发料单→上传并自动识别，新增独立“客户料长核对”卡片。
2. 每个订单项次分别展示规格、材质、客户料长、实际料长、差额和来源行。同产品去重不会漏掉关联订单项次。
3. 支持复制反馈清单和下载UTF-8 CSV清单；CSV防止客户文本被作为公式执行。
4. 可先在产品规格资料补录实际切料长，再点击“重新核对实际料长”，不必重传文件。重新核对后撤销旧勾选。
5. 提交事务内复检实际值和档案归属。确认摘要过期时返回最新提醒，保留预检状态和文件，不标记导入失败，也不写入业务数据；用户再次知悉即可提交。
6. 导入历史保存当时的核对快照、确认人和确认时间，历史查询/下载不根据当前档案重算。部署前的旧历史不补造提醒或确认。
7. 无模型迁移。新增接口与下载沿用所属用户和只读账号权限保护；其他客户图片、内部总表、产品资料和发料导入不受本次确认要求影响。

## 已验证

- 后端全套635项通过，199.849秒；新增18个测试方法，覆盖±5mm边界、小数超差、缺值、明确文本/复杂文本、档案歧义、逐订单项次、权限、历史快照、过期确认、原值保护和批量查询。
- 500个附加订单项次只增加一次批量产品查询，不逐行查询数据库。
- TypeScript、ESLint及生产构建通过；`makemigrations --check --dry-run`无变化。OpenAPI生成退出码0，库存接口既有序列化注解诊断仍存在，不把它描述为零告警。
- Chromium 360、390和1440像素完成预检→提醒→知悉→重新核对撤销勾选→再确认导入流程；无页面脚本异常，提醒卡片和抽屉无横向溢出。使用模拟API，不代表Android真机验收。
- 新鲜线上数据库隔离副本：101条产品档案，其中18条实际切料长已填且均为可明确识别的毫米值。最近一份翔邦导入4个项次，只读比较耗时1.25ms；复制为5倍20个项次耗时0.92ms。仅为比较函数单次样本，不是端到端P95性能结论。
- 副本演练请求状态依次为409（未确认）、409（确认后实际值变化）、200（重新确认导入）、400（阻止同批次重复导入）。订单数量2400、关联产品和手填实际长/重断言正确；全部写入回滚后所有模型行哈希和SQLite序列与演练前相同。
- 完整本机证据目录：`.codex_tmp/cut-length-qa/`；真实数据库和业务快照不提交公开仓库。
