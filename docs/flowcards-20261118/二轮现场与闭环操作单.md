## 2. 普通用户连续页面录像

使用系统屏幕录像工具完整录制，不通过 API 代替按钮操作。若某一页面入口不存在或无法提交，就记录为未通过并保留报错，不预置记录跳过。

1. 订单完整查看→工序流转卡。核对订单项次、产品和返回入口；按已确认要求制卡，明确这只是计划，不新增生产件数或库存。
2. 常规卡尺寸只选线径上限，内径仅产品识别；另一个订单明确加测内径。PDF 及页面限值应同源，空下限不能显示为 0。
3. 输入线径 3.06，实际测量人/业务时间、测法及依据；保存应显示“超上限 0.01 mm，待复核”，不要求另填异常，不自动扣库/退货/判整批。
4. 从首屏复测入口填 3.04、实际处理人和业务时间。原 3.06、人员、时间保留；有效提醒解除。另测仅变“未测”不能解除；未知方法读数可保存但不得假正常。
5. 从实际二烤页面选择两张卡，登记实际盘号、范围、温度、分钟、人员时间，登记一张本厂当批料胶片代表两卡。不得直接照抄建议。
6. 从该二烤“记烤后硬度”进入，核对日期/盘号/胶片/料批/代表卡，填读数一次。两卡均追到同一检测，不能各算一次产量。让其中一卡另一次二烤不随胶片，该次必须仍未测。
7. 从原品检页面登记并确认一笔新合成 **100 件**出货，关联两张内部卡为来源集合。净交付为 100，不因关联两卡变为 200；没有确定逐卡份额时不能各记 100。
8. 数据集 A 使用客户流程卡扫码退回整批，原有效量应由 100 回冲至 0。原出货已填品检员不重复要求补录，确实缺原人员才补录。再次出货填本次实际人员，发 100 后净交付回到 100，不能重复计成 200。
9. 数据集 B 另建独立的 100 件出货，使用无扫码整批退回入口，核对逐项次回冲预览再确认，净量同样为 100→0→100。两入口不可互相污染，不能用同一批重复退货冒充两套验证。
10. 回原卡追溯查看原出货、各轮退回、再次出货及原测量；原冻结 PDF 不变。没有实际返工作业记录时只能说系统未登记，不能从退货/物流推成返工完成。

这里的 100 件是演练目标，不是本轮已经通过页面登记的结果。原分摊规则继续有效，不为测试重分正式历史。

## 3. 实印、手查与安卓实扫

1. 本轮样卡是 **190×130 mm 横版工序卡，不是70×50货架标签**。打印机与纸型须匹配，100%实际大小，不用“适合页面”，关闭浏览器页眉页脚。
2. 需整模和不需整模各打一张；用尺量尺寸，确认实测格、签名线、二烤日期盘号有足够书写空间，未裁切或缩放。
3. 原号分成两行时第一行末尾“-”保留；照纸面完整手输应开同一卡，错一位不能误开，不能只按尾号猜测。
4. 安卓 App 扫内部二维码，打开正确完整卡号；再扫客户流程卡、库位码和未知码，确认分流不误建客户卡。
5. 实际手机上录 3.06、看首屏、复测、选择二烤胶片；软键盘/时间控件不遮保存，姓名、卡号、来源不截断，返回不误丢数据。
6. 实际 App 下载并重开冻结 PDF。下载不自记打印成功；成功/未知的确认仍由实际出纸结果决定，补打同号。
7. **不要仅因软件通过就把纸放进二烤炉。**纸、墨、胶黏剂与夹具的耐温、挥发物及质量风险须由现场单独确认。

## 4. 弱网与并发（仅隔离站）

- 同一保存操作模拟断网/响应丢失后，先恢复网络、查询原结果，用原请求号重试；应只有一条实际事件，不换新号盲重建。
- 若收到 503，记录发生步骤、请求号、恢复方式及最终数量，不删除失败证据，也不因最终唯一就写“所有请求成功”。
- 两台设备同卡登记/复测需核对链尾，不能从原超限分叉产生两个互相冲突的“已处理”。
