# 工序流转卡：现场/设备验收操作单

此文件是待执行清单，不是已通过记录。先用隔离测试站与合成单；正式站仅在批准上线后只读核对。不要用真实出退货制造测试记录。

## 设备与记录

记录时间、测试站版本、浏览器/WebView版本、设备、网络/Wi-Fi/4G、纸张包装毫米尺寸、打印机驱动纸型。截图前遮住真实人员、客户敏感信息，不含账号密码/令牌。

## 1. 页面和扫码（PC、Android App分别做）

1. 从订单项次、生产任务进入，核对产品ID/订单ID/真实Run ID及返回按钮。已有卡组应先出现，不将原计划重复生成。
2. 用一个无任务/无标准/无模数样本保存准备组。无生产任务或台账新增；补齐80模和需/不需依据后，修改原准备组并生成，仍是同组一张80M，不是新生产任务。
3. 扫内部卡，只打开详情；再在客户流程卡扫码区扫同码，应清楚提示类型不对，不进入未知客户卡新建。客户卡、库位码和故意未知码分别验证。
4. 收起历史，检查扫码不先下载所有原图。展开事件/照片/追溯分别加载；20项以上能翻页，失败不能显示“无/0/正常”。
5. 手机宽360/390/430、平板768、PC1366各检查：横向不整页溢出、下拉完整姓名、键盘不挡确认、按钮能点、不丢原输入、返回保来源。大表允许表内横滑。
6. 原图、PDF未登录/匿名必须拒绝。只读账号能看/下载，不能生成/确认标准/作业/来源绑定/复核/补打。普通账号开关关闭时写入也应拒绝，读取已有卡保留。

## 2. 相机与网络分开计时

- 相机端到端：从稳定识别二维码（提示音/识别画面）到正确卡号和身份可见，连续20次记录；另测有100条历史的同卡。两次各算P50/P95和错误数。不能把启动相机时间与接口时间混为一个结论。
- 网络读：在已登录隔离站手动粘贴`scripts/flowcards_readonly_benchmark.js`到开发者工具，再运行`await measureFlowCardReads('ERPFC:<隔离卡UUID>',20)`。脚本只GET、最大50次、不打印业务内容或凭证。它不含相机和页面绘制，不能单独证明2秒目标。

## 3. 弱网、重试与并发（隔离站）

1. 制卡提交前断网：保留输入及请求号；恢复后按原请求重试，核对只一个组及固定卡号。
2. 提交已到服务器但客户端丢响应：先按请求号查原结果，不能换号盲建。修改原输入前核对旧请求是否成功。
3. 两人同时生成同一组/打印同一卡：冲突提示可接受，后续核对原结果，不允许重复卡或同时两个“补打1次”。记录503/409，不能仅因数据库最终唯一便写所有请求成功。
4. 错来源卡一起出货：确认整体失败、原单仍草稿、没有交付或来源孤儿。网络不明不能误报已出货。
5. 出货更正后旧来源保原证据并待核对，人工确认或撤销留原因；不能按新Line ID自动改接另一个包。

## 4. 32开草稿实印

1. 先确认包装实际毫米；与PDF190×130不符先停止，不能靠缩放掩盖。
2. 横版、单面、100%/实际大小；关闭适合页面、页眉页脚及多页合一。驱动纸型同PDF。
3. 各试一张需/不需整模：日期、完整卡号、二维码、四外观、上下模/硬度/尺寸、定点及人员、洒油三选、二烤/烤后、右下品检员均可读；上下模实测区能实际笔写。
4. 检查长字段续页与主卡同号随卡；20/21张首中尾序号，尾50M。照片/签名不被软件默认合格。
5. 打印任务先只确认真实成功范围，其他保持未知；只继续未完成的卡。关闭预览/下载不能增加补打次数。
6. 一批20张试只成功18张，核对两张仍待核对，成功18张不被全批算补打；再按原任务核实余两张。原纸丢失后补打同ID；不得用补打冒充拆出的独立包。

## 5. 业务人员核对

- 400总孔、396有效孔、4定点，再记4仍396；位置变化不自动扣孔，不算出固定报废量。
- 无数字记录写“系统未登记”，不能断言现场未做；未解决异常不因整模/毛边/出货消失。
- 同次共同测量引用两张卡只一条事实；实际人员与登录人分开。
- 手工库存出库和品检出货分账；制卡/绑定均不扣库，不自动改待检为合格。
- 一次出货多来源、跨订单份额及两轮退回再发数量应按原服务对平，来源集合不重复累计实物量。
