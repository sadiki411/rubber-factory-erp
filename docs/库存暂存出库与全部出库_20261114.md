# 库存暂存出库与“全部出库”调整

日期：2026-11-14（北京时间）。范围仅为库存人工出库；不调整品检出货、订单交付或历史库存账。

## 业务依据与原因

用户明确说明库存还承担暂存功能，待检、不合格的产品也需要直接取走，不应为了出库而先改为合格；同时希望在数量旁一键填入全部剩余数量。

旧行为来自两层相同约束：`InventoryPage` 仅显示 PASSED 容器，`create_inventory_outbound` 也仅接受 PASSED。这是原有出库规则，现在按实际业务需求调整。本说明取代《库存待检状态修复与验收_20261022.md》中“只有已检合格才提供办理出库”的旧限制，**不废弃实际检验合格需要品检员的规则**。

## 当前规则

|状态/情况|库存人工出库|
|---|---|
|已检合格 PASSED|允许|
|待检 WAITING|允许，无需补品检员或改状态|
|不合格 FAILED|允许，保留不合格标记|
|冻结 HOLD|仍限制；先核实并解除主动冻结|
|已空、已关闭、数量为0|不允许|

- 每行显示容器、规格、质量状态及当前可出数量。待检/不合格库位详情直接提供“办理出库”。
- 数量旁“全部出库”只填入**当前选中容器、当前读取的剩余件数**，不立即保存；点击“确认出库”才生成出库单和流水。每个容器单独填充，不代表全仓出库。
- 允许填充后改为部分数量；切换容器清空旧数量，避免把上一筐数量误带到下一筐。未选容器、正在读取、读取失败或只读角色不能使用快捷填充。
- 服务端保存时重新读取余额，禁止超量、0/负数及重复容器行；某行失败回滚整张出库单。前端读取的全部数量若已超过最新余额，拒绝保存，不静默多扣或改数。
- 部分出库：余额减少，原库位保留。全部出库：余额归0、容器变 EMPTY、释放库位，可重新入库。
- 不修改批次质量状态、品检员或检验日期；新出库流水在原因中记录“出库时状态”，以免后续状态调整混淆。
- 人工库存出库不自动生成客户出货、不改变订单净交付、不触发流程卡二次扣库存。关联订单仍仅为原有引用用途。
- 汇总仍将已检、待检、不合格、冻结分别统计，允许人工出库不代表待检/不合格成为合格可用库存。
- 不改数据库结构、不迁移或重算历史记录。新增出库可以反查原容器、原批次和库位流水。

## 测试范围与证据

所有写入测试仅在 Django 自动创建的隔离测试库运行，不在正式账制造测试出入库。

- `InventoryApiTests.test_temporary_stock_partial_and_full_outbound_keeps_quality_and_frees_location`：待检/不合格/合格分别部分→全部出库；保留检验事实，释放库位，重复扣空被拒，流水守恒且不生成品检出货。
- `test_temporary_stock_outbound_does_not_change_linked_order_delivery_or_status`：即使引用订单也不改交付或订单状态。
- `test_mixed_temporary_outbound_is_atomic_on_overdraw_and_valid_when_corrected`：第二行超量整单回滚；更正后多状态混合出库成功。
- `test_mixed_qualified_and_frozen_outbound_rolls_back_every_line`：主动冻结仍阻止整单，不部分扣账。
- `InventoryTopUpTests.test_waiting_top_up_can_be_manually_outbound_without_becoming_qualified`：待检追加入库后能人工出库，仍计待检、不计已检可用。
- 原有负数/0、重复容器、重复出库单号、已空状态、质量更正及只读权限回归保留。
- 前端 `InventoryPage.test.tsx`：待检/不合格入口、逐容器全部填充、不自动保存、手动改数、切换清空、多容器分别填充、冻结不出现候选、失败保留表单、质量状态和原接口边界。
