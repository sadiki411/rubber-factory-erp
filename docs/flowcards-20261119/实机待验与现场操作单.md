## 1. 准备与证据记录

先记录测试日期、代码提交、安卓App版本、机型/系统、隔离地址、网络、实际操作者。目标隔离环境需与待试版本相同、写入开关明确开启；禁止复用正式库或正式账号凭据。Android相机通常需要已配置可信HTTPS/应用权限；如使用非正式地址，应由维护者配置隔离版本，不修改正式App指向。

不要在录屏中输入/展示密码。先登录普通员工，再开始系统连续录屏；保存原始视频，不剪掉失败/重试过程。若要分两段，分别为SCAN和MANUAL，每段从选合成订单到原卡回查连续记录，视频内先展示合成规格和订单号。

## 2. 两套闭环的页面操作（不能写正式账）

### SCAN

1. 合成订单60件+40件，同客户、同明确产品，两张内部卡。记录完整卡号与客户卡号，生产量未知保持未知。
2. A卡11:00实测3.06，隔离上限≤3.05；再补10:00的3.04，确认11:00红提醒仍在；11:20同范围3.04才解除，原事实均可查。
3. A+B同烤，胶片仅代表A，B页不可登记该片；再共同胶片确实代表A+B时录一次，两卡查同事件；A第二次无随片要独立显示未测，不沿用70。全部为合成标准，不套真实客户。
4. 首发100，预览60+40。选两内部卡为共同来源但份额未知，不让各卡各出100。用客户卡扫码退100，核回冲60+40、责任沿用原品检员；原卡再发100，重选本轮品检员。
5. 原内部卡查首发、退回、再发；保存各阶段订单净数100→0→100及原分摊明细。截图不能替代连续录像。

### MANUAL

另两项次60+40、另客户卡与内部卡；首发100后，从“登记整批退货返工（无扫码）”选原物理批号，预览回冲60+40。本轮已发现退货未承接原客户卡，净数到0但无法直接再发，**不要更改数据库或用新首发假装闭环**。

后续仅在用户授权补修、通过测试后，再从全新合成样本重走100→0→100。验原客户卡与当前退货一致、单轮一次再发、两入口同数量口径、多卡歧义不猜配。未补修前该项标失败即可，无需反复试正式货。

## 4. 性能20次采样及统计

从空白 `field-metrics.csv` 填写，至少分别完成普通卡20次、历史多卡20次，不把同一卡重复数当作历史记录多。保留冷/热、网络条件和失败，不只挑秒开的记录。

- `scan_ready`：起点相机成功识别/手查确认，终点正确卡号与关键详情已呈现、操作按钮实际可用。失败计入失败数；相机打开到识别另可记为 `camera_recognition`。
- `ship_save` / `return_save`：起点确认保存，终点成功提示且刷新显示唯一结果；不能只计HTTP首字节。
- `save_retry`：先在合成环境模拟请求已处理但响应丢失，再用原请求键重试；记恢复耗时并核对无重复事件/分摊/回冲。不要用换key的新单替代。
- 每类报告P50（中位数）、P95（成功样本升序第ceil(0.95×n)位）、成功/失败/未测数；失败不进入成功耗时分位，但必须独立列出，不能删去。
- 本轮没有真实结果；表格留空即未测。工具不会把空白当0。
- 原 `scripts/flowcards_readonly_benchmark.js` 只测GET网络往返，可作辅助；不含相机、详情绘制与可操作状态，不能单独证明扫码2秒达标。

填写起止时间用同一计时基准（例如录屏帧时间换算毫秒），不能混合手机时钟与服务器时钟；备注测量方式。人工按秒表可保留，但注明误差。文件不要填真实客户隐私或账号密码。

统计命令（只读CSV；项目Python即可）：

```powershell

```

脚本可用 `--template 路径.csv` 生成40次扫码+保存/重试空表，只在新路径创建，不覆盖已有测量。

## 5. 目标同版本隔离恢复与回退

1. 用户指定目标隔离环境；确认不是正式账，记录代码/配置/DB路径/私有文件目录及合成标签。管理员记录秘密信息只在私下保管，不入审阅包。
2. 验普通员工、只读、未登录：读与写权限分开。切写开关关闭后，新增/复测/制卡写被拒，卡片与旧冻结PDF仍可读。
3. 备份隔离DB及对应私有PDF/图片，记行数、业务摘要、文件SHA。恢复至新空路径，核对卡、事件、分摊/回冲、来源集合及冻结文件相等，不靠页面总数近似。
4. 停止隔离写入，再切回基线只读服务；先查原卡、事件、原PDF。旧服务没有新record路由，应明确404，不能自动落到客户卡或创建新身份。
5. 本地已验证旧代码只读兼容；目标服务切换、附件路径、App缓存/版本仍需实际核查。旧版能读不等于可继续写新结构事实；未经确认不开放旧版写入。
6. 记录失败与恢复方案。若PDF缺失/摘要不符/数量不平，停止试点审批，不在旧账上猜补。
