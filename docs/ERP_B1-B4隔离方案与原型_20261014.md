# ERP B1—B4 可审阅方案与隔离原型

本文件只提供方案和脱离正式业务流程的原型，不新增正式表、不改正式历史、不自动启用 N1—N9。正式业务规则和实施范围由用户确认后再进入开发。

可点击原型：[打开隔离演示](prototypes/erp-next-stage.html)。所有DEMO数据均为合成；没有ERP接口或业务保存，CSP禁止网络连接及表单提交。用浏览器打开即可。本文件的JSON只是结构示意，不是正式数据证据。

## B1：全厂待办 + 订单完整查看（建议第一批）

### 目标

把已有事实记录串起来，先让管理人员从一个入口找到“要处理什么”，再能从订单项次看到完整来源。待办不另建一套需要人工同步的平行账。

### 数据联动

`QualityOrder` → 生产任务/日报 → `ProcessCard` → `QualityShipmentBatch/Line` → 分摊表 → `QualityReworkCase/Attempt` → 成品库存容器/库位（仅引用已存在的库存记录）。库存继续独立于订单和流程卡，不按规格猜绑。

### 首批验收

从待办打开一项欠交订单，能看到卡号/批次/分摊/退货来源；返回列表后保留筛选；同一事实不在待办和订单页重复累计。交期缺失显示“未登记”，不按品检员猜负责人。

## B2：真实返工过程 + 一条后工序交接试点

### 先做的范围

只选择一条真实常用路线（例如“待返工 → 处理 → 待复检 → 合格/报废 → 再次出货”），沿用已有退货批次，不创建第二份产品数量账。

### 原型字段

```json
{
  "process_event": {
    "source_return_case_id": "R-待用户确认",
    "product": "由物理出货批次带入",
    "operator": "实际返工人员，不能自动代填原出货品检员",
    "occurred_on": "处理日期",
    "input_quantity": null,
    "output_quantity": null,
    "scrap_quantity": null,
    "status": "PROCESSING | WAITING_REINSPECTION | COMPLETED | SCRAPPED",
    "evidence": "照片/备注/复检依据，可选",
    "correction": "更正来源，不覆盖原事件"
  }
}
```

原出货负责人、责任品检员、实际返工人员、复检人员、再次出货人员是不同事实，不能互相自动代填。用户确认这条路线的字段和结案规则后，才实施正式录入。

注意现有model并非空白：`QualityReworkAttempt`已有人员、日期、投入/处理/合格/报废和状态，但当前整批客户退货验证要求投入/处理等于整批数量；扫描卡的下一轮必须由再次退货扫描产生，不能人工随意增加。所以上述“分段800件”候选不能直接塞入现有整批attempt。

候选①整批轻量真实作业确认，沿case/attempt补人员、日期和整批处理依据（字段少，但不反映分段工作）；候选②独立作业/交接事件，明确引用case/物理批次，支持实际分段，必须防止与自动整批attempt重复累计。请本人选定；推荐只试一条现场真实路线。手机负担为人员、日期、实际处理量、结果4项，照片/说明可选。处理完成、复验通过、再次出货必须各有事实来源。

## B3：产品经验档案

### 复用现有资料

产品规格、原始/实际切料值、历史单重、图片、工艺文本和当时快照作为来源；档案版本只引用已确认内容，未验证参数显示缺项，不由 AI 猜填。

### 隔离原型

```json
{
  "product_experience_card": {
    "product_identity": "ProductSpecification#ID + 规格 + 材质",
    "applicable_molds": ["已有模具型号"],
    "confirmed_parameters": [{"name": "加硫时间", "value": null, "unit": "秒", "source": "待确认"}],
    "common_defects": [{"name": "空洞", "handling": "待现场确认"}],
    "photo": "已有产品照片或空",
    "version": 1,
    "effective_from": null,
    "history": []
  }
}
```

验收重点是换人/再次开工时少查一次手工账，并能看见资料来源和版本；建立档案不代表所有工艺参数已经验证。

## B4：规则核对与候选方案

### H3 候选：码与对象

1. 已知流程卡/库位码：直接关联并显示对象。
2. 首次未知码：进入“待确认名单”，允许管理人员选择对象后建立关联。
3. 格式合法但对象不匹配：明确提示“码存在但对象不匹配”，不静默新建。

### H4 候选：机台/模具状态

1. 允许“上模位置”和“手工生产任务”独立存在，分别显示来源。
2. 任务结束但模具未归位：产生待办，不自动取消任务或移动模具。
3. 同台多模/试模：先按真实事件区分，再由用户确认是否限制并存。

原型只展示状态和冲突提示，不写入、不取消历史。正式采用哪一项需要结合现场例子确认。

## 实施顺序与确认点

推荐顺序：B1 → B2 单路线试点 → B3 → B4 规则落地。每批都先做隔离页面和样例数据，再决定正式表单、权限、报表和历史迁移；没有用户确认不接入生产流程。

## 实际实体核对与边界

| 链路 | 当前代码 | 只读联动边界 / 缺失事件 |
| --- | --- | --- |
| 订单项次 | `backend/quality/models.py`：`QualityOrder.id/order_no/item_no/due_date` | 项次ID为身份，订单完成遵守既有人工规则。 |
| 发/来料 | `backend/orders/models.py`：`MaterialReceipt.order` | 只显示明确FK，无关联待关联，不按规格猜绑。 |
| 合并生产 | `backend/production/models.py`：`ProductionRun.order`、`ProductionRunOrder.order`、`ProductionDailyLog` | 总模数/折算件数只累计一次；上下机`loaded_at/unloaded_at`缺失则不算实测效率。 |
| 最终良率 | `ProductionYieldRecord.confirmed_at/confirmed_by` | 没有确认就未登记，不从“未出货差额”生成库存。 |
| 卡/物理出货/交付分摊 | `ProcessCardUnitBinding`、`QualityShipmentBatch/Line`、`QualityShipmentOrderAllocation` | 卡号快照、物理批号和交付归属分开，不覆盖旧身份。 |
| 退回/作业 | `QualityReworkCase/Attempt`、`QualityReturnAllocation` | 整批回冲按原分摊；真实分段作业及后工序交接尚缺完整事件。 |
| 库存 | `backend/inventory/models.py`：产品/批次/容器/库位/流水，`InventoryOutbound.order`可选 | 入库独立于订单和卡。仅展示明确出库单引用；同规格库存池不自动归属订单、出库单不再叠加进出货量。 |
| 产品经验 | `ProductSpecification.actual_material_length/actual_cut_weight/primary_curing/secondary_curing/effective_cavities/mold_model/main_image`；`ProductInspectionCriterion`、`ProductUnitWeight` | 现有自由文本不能未经确认解析成有效工艺；缺“来源—验证—本人确认—版本生效”生命周期。先做只读经验卡，后确认版本，不改历史快照。 |
| 位置 / 任务 | `backend/molds/models.py`：`MoldAsset/RackSlot/MoldMovement`；`ProductionRun` | 位置事件与生产任务不同来源，差异不能直接证明谁错。 |
| 分析 | `backend/analytics/services.py`；品检summary | 同一来源事件唯一累计，缺作业不通过再出货猜填。 |

## 第一批候选决策与验收

- B1排序：交期优先且缺交期单列（建议）；等待时间优先；本人维护插单优先级（增加操作）。未知负责人不从品检员猜。
- B1先只读，零新增现场必填；订单全过程从明确关系串起，返回保留筛选。分页加载数不能当全厂待办总数，需要服务端带范围聚合/分页。
- B2先选整批作业确认或分段事件，再确认一条真实路线；部分、报废、重复加工、更正的数量规则先隔离验算。
- B3候选：只读经验卡（建议）→本人确认与版本→缺陷照片和经验。确认一个参数不代表全部参数已验证。
- B4未知码：只读提示并人工确认明确来源（建议）；单独待确认名单；新码严格格式+历史白名单。现有可识别合法码不一刀切拒绝。
- B4状态：位置与任务独立展示（建议）；差异提示人工核对；强制正式任务绑定位置（需先确定试模、多模、换急单及清零复开）。不自动取消任务或移动模具。

原型验收：DEMO-A需求10,000，分摊出货8,000−回冲2,000=净6,000，欠4,000；物理出货12,000分摊A8,000/B4,000，退物理批3,000回冲A2,000/B1,000；合并生产总15,000不分别给两单各累计。待办→订单→原出货/退回→返回保留条件。工序表单仅本页预览，经验确认与状态候选仅改变演示。

N5—N8仍为后续路线图。本轮没有正式实施这些新增业务规则，用户本人审阅后确定第一批范围。
