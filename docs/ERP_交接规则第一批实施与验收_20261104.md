## 2. 已完成的本地代码

### 2.1 自动分摊身份边界（R001、R027 / Q1）

根因：原候选只看规格、材质和未完成状态。工厂由单客户发展到多客户后，相同文字不能证明可互相填单。

新规则：来源先填，超出只补同客户、同产品档案ID、同规格材质的开放订单，再有剩余回来源记超额；原交期排序、整数件数和重量尾差规则不变。

- `orders/identities.py`从明确客户名及已知客户单据类型识别客户。`source_system`常是供应商，不能见同字符串就认作同客户。证据矛盾或未知不自动扩单。
- 历史来源不明的订单仍可被明确选择正常出货，不能为了恢复自动分摊而批改历史客户。不同客户确需出货时，人工明确选来源并另列明细；不存在按同规格偷偷自动补入。
- 同批多明细的预览与确认共用服务端余额。保持物理行顺序，例如A/B/A，不能先按规格材质合成一组，也不能给每行重复使用同一欠数。
- 未改变物理包、流程卡及原交付分摊的业务定义。

主要位置：`backend/orders/identities.py`；`backend/quality/services.py`的两个allocation planner；`backend/quality/views.py`的`allocation_preview`；`frontend/src/components/QualityWeightShipmentDrawer.tsx`。

**尚未覆盖的边界：R010/R011发料导入、历史自动补链仍是原机制，本批没有声称已经与新的出货分摊边界统一。发料来源单位不是客户身份，缺明确客户证据时不可简单复用同名字段。保留未关联记录、不批量补链；这是下一批需处理的技术/来源缺口，不需重新询问已确认的同客户原则。**

### 2.2 更正保留历史归属与真实返工（R041 / Q3）

根因：原出货更正会重放确认，并将下游Attempt数值按新旧基数比例改写；应用新客户过滤后，连仅改备注也可能改变历史分摊。

本批处理：

- 物理件数、来源订单、卡和明确产品身份不变时，沿用原分摊件数、顺序、超额标识及订单/规格材质快照。若仅重量改变，仍保持原件数归属，必要时重分重量尾差。
- 提前预留本批所有沿用的旧份额，避免前面被修改的行占用后面需要保留的份额。
- 原出货更正后退回会计基数可按现有机制重接，**不再比例改写**实际投入、处理、合格、报废件数与重量；差异写入案说明，作业前后快照进入原有批次修订。
- 原基数改变后，给同一历史作业只补说明，不会要求为了通过校验先把旧投入改成新基数；新增作业或修改投入仍按当前来源约束验证。改绑到另一退回案不适用该例外。
- 删除原包/明细、改变包装布局若会让实际作业失去来源，事务拒绝并明确说明，原单和作业保持。无实际作业的误包仍沿原更正机制处理。

**限制**：本批未新增独立、不可变的实际作业更正/冲销事件表。现有Attempt的人工编辑不因此自动获得完整字段审计。该正式写流程在下一阶段方案中；不能将本批保护原值夸大为全系统审计完成。

### 2.3 班次、协作和效率解释（R022、R024）

- 前后台班次建议统一北京时间07:30至19:30为白班，其余夜班；前端不依赖设备所在时区。
- 每个统一员工协作记录显示全部参与模数、折算产量和参与天数，分别标主作业/协助。主员工同时出现在协助名单时不重复。
- 全厂、机台、日期及订单的物理日志仍只算一次，不能将各人的参与量再求和当全厂产量。
- 页面明确“折算工时/上下机间隔”，不是个人实测净工时或真实每小时效率。
- 不重写旧班次；真实个人时段、休息/暂停扣除仍未建成，不能据此作精确计薪。

主要位置：`backend/production/serializers.py:ProductionCounterLogSerializer.suggested_shift`、`backend/analytics/services.py`、`frontend/src/production.ts`、分析页面。

### 2.4 B1：全厂待办与订单完整查看（只读）

新增入口：侧边栏、工作台按钮及订单行的“完整查看”。

待办列四类事实：开放订单欠交、未结退回/返工及标记完成但未再发、非合格状态的在用库存容器、无订单FK的发料。各类是事项条数，不相加为产量，不按责任品检员猜处理负责人。

订单完整查看分8节：生产任务、明确关联发料、来源流程卡、重量/卡出货、件数出货、退回/再发、件数退回、明确引用的人工出库。

- 顶部净交付使用现有统一口径；原出货归属与退回分列，不能再将页面各项相加。
- 物理原量、本项次分摊量、净交付分开。生产显示机台、已登记参与人员、上下机时间与模数折算说明，不冒称实测良品。
- 行卡FK缺失但有批级绑定时，显示批级候选并说明未逐行猜配；不凭同规格补卡。
- 库存仅展示`InventoryOutbound.order`的明确引用；不把同规格库存猜属于该订单，不增加客户净交付。
- 缺记录/不适用显示明确文字；加载中用骨架，失败显示错误，不显示假0。分类汇总是全搜索范围，不以当前页长度冒充总数。
- 服务器分页，每页最多50条；返回待办保留搜索、类别和页码；非法订单ID不无限转圈。
- 两个新接口只提供GET，沿用登录/只读权限，没有公开完整订单或人员资料。

接口：`GET /api/orders/workbench/`、`GET /api/orders/orders/{id}/overview/`。

**限制**：该页不新增接单人、承诺时间或人工关闭待办，不推断二烤/去边/机检进度。生产与物理成品包仍没有统一身份桥接；不是完整现场执行系统。旧手工分析补录不自动并入生产进度。待办读取现有单一订单状态；Q2双状态已明确不采用。
